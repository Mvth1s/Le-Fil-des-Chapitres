## Points contrôlés

| Point | Statut | Détail |
|---|---|---|
| Rendu de `q` | Conforme | `q` n'est lié qu'à `v-model` d'inputs (`AppNavbar.vue:101`, `catalogue/index.vue:161`) : valeur d'attribut échappée par Vue. Aucun `v-html` ni `innerHTML` dans `frontend/app`. |
| Construction d'URL | Conforme | `navigateTo({ path: '/catalogue', query: { q } })` (`AppNavbar.vue:28`) et `router.replace({ query: { ...route.query, q } })` (`catalogue/index.vue:67`) : objets `query`, encodés par vue-router. Aucune interpolation de `q` dans une chaîne d'URL. |
| Redirection ouverte | Conforme | Chemin fixe `/catalogue` (navbar) ; `router.replace` ne change que la query de la route courante. `q` ne sert jamais de cible de navigation. |
| Type de `q` | Conforme | `queryText()` n'accepte qu'une chaîne (`typeof === 'string'`) ; `?q=a&q=b` (tableau) ou `?q` absent donnent `''`. |
| Sans JS | Conforme | `<form role="search" action="/catalogue">` sans `method` = GET natif, `input name="q"` : `/catalogue?q=...`. Le SSR initialise `search` depuis `route.query.q` et le filtrage (`computed`) est rendu côté serveur. La Basic Auth du frontend reste appliquée (middleware serveur). |
| Transmission au backend | Conforme | Recherche entièrement côté client : `useFetch('/api/webtoons')` sans paramètre, puis `filterAndSortWebtoons` / `normalizeSearch` (`utils/search.ts`, regex à classe de caractères, sans risque de ReDoS). `q` n'atteint jamais le backend. |
| Fuite vers un tiers | Conforme | `Referrer-Policy: same-origin` (`nuxt.config.ts:43`), `connect-src 'self'`, polices auto-hébergées, `referrerpolicy="no-referrer"` sur les couvertures externes. Aucun script tiers ni analytics. L'URL contenant `q` n'est donc jamais envoyée hors de l'origine. |
| Lien d'évitement | Conforme | `href="#contenu"` statique (`app.vue`). |
